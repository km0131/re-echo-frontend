# デザイン（画面設計）

画面デザイン「同窓会日程調整 画面デザイン」（8画面、幅390px）を、実装用のルールに書き起こしたものです。
テーマは **「甘酸っぱくて懐かしい青春」**。方眼ノートに貼ったポラロイド写真のような見た目にします。回答のしやすさは装飾より優先します。

### 1.2 フォント

Google Fonts から必要なものだけ読み込む。

```html
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Zen+Kurenaido&family=Noto+Sans+JP:wght@400;500;700&display=swap">
```

| トークン | フォント | 使う場所 |
| --- | --- | --- |
| `font-hand` | Zen Kurenaido | 見出し（h1・h2）、ひとことコメント、ポラロイドのキャプション、カウントダウンの数字、ロゴ「出欠帳」 |
| `font-sans` | Noto Sans JP（400/500/700） | 本文、ラベル、ボタン、表、フォームの値、日時 |

手書き風フォントは太字にしない（`font-weight: 400`）。

### 1.4 形・余白

| 項目 | 値 |
| --- | --- |
| 画面の左右余白 | 18px（ゲート・ログインは28px） |
| セクション間 | 22px（ギャラリー・管理は18px） |

| 部品 | 仕様 |

| `Button`（副） | 高さ52px、白地 card、枠1.5px navy、文字 navy・700 |
| `Button`（点線） | 枠1.5px 点線 navy、背景透明。「＋ 新しいイベントをつくる」「＋ 候補日を追加」に使う |
| `SmallButton` | 高さ44px、角丸10px、枠1.5px navy、文字13px・500。注意系（再発行など）は枠 maybe・文字 maybe-ink |
| `TextInput` | 高さ50〜52px、角丸10px、背景 card、枠1.5px（フォーカス中・入力済みは navy、未入力は field）、文字16px |

| `FilterChip` | 高さ36px、角丸18px。横スクロール。仕様は Pill と同じ |
| `Card` | 背景 card、枠1px line、角丸14px、余白16px、子要素の間隔12px。強調時は枠1.5px navy |
| `Polaroid` | 白枠 card、余白 上左右8〜12px・下30〜44px、影あり、`rotate(-3deg〜+2deg)` のどれか。下余白にキャプション（font-hand、13〜18px、sepia-ink、中央） |
| `Tape` | 幅60〜88px、高さ20〜24px、色 tape、少し傾ける。ポラロイドの上辺中央に重ねる |
| `StickyNote`（ひとこと） | 背景 card、角丸4px、余白12×14px、軽い影 `0 2px 6px rgba(43,52,72,.1)`、`rotate(-.8deg)`/`rotate(.6deg)` を交互に。本文 font-hand 16px、下に「― 名前」11px muted |
| `Tag` | 11px、角丸4px、横余白8px。塗り（navy地に paper）または枠線（sepia / off） |

| `TopBar`（戻る付き） | 左に44×44pxの戻るボタン（くの字の線アイコン）、右にイベント名13px muted |
| `BottomBar`（固定CTA） | 画面下に固定。背景 `rgba(246,241,231,.94)`、上に1px line、余白14px 18px 24px。中に主ボタン |
| `Tabs` | 地 highlight、角丸12px、余白4px。各タブ高さ40px、選択中は card 地・navy・700。件数バッジは maybe 地の小さな丸 |

アイコンは線のSVG（`stroke-width:2`、`stroke-linecap:round`）を自前で持つ。アイコンフォントや絵文字は使わない。

### ◯△✕ の表示ルール
- 記号は全角の「◯」「△」「✕」を使う。
- 色は yes／maybe／no。**記号を省略して色だけで表すことはしない。**
- 集計の書き方：`◯18 △4 ✕2`（記号だけ色付き、数字は ink）。

## 3. 画面ごとの仕様

### 3.1 合言葉ゲート `/e/:slug`（Main）
上から中央寄せ、上余白56px、間隔28px。
1. **ポラロイド**（幅268px、写真244×244px、`rotate(-3deg)`）。上辺中央にマスキングテープ。写真は **public 写真**（なければ photo 色の下地）。キャプションはイベントごとに設定できる文言（初期値「あの頃の放課後」）。
2. 英字キャッチ `CLASS REUNION {年}`（sepia、字間 .2em）
3. イベント名（font-hand 32px navy）
4. 補足「クラスのみんなだけが入れるページです」
5. フォーム：ラベル「合言葉」→ パスワード入力（placeholder 例「例）担任の先生のあだ名」）→ 主ボタン「ひらく」→ 補足「一度入ればこの端末では次回から省略されます」

- 間違えたら入力欄の下に `maybe-ink` で「合言葉がちがいます」。回数制限にかかったら「少し時間をおいてもう一度試してください」。
- 通過済みの端末は、この画面を出さずにイベントトップを表示する。

### 3.2 イベントトップ `/e/:slug`（Top）
1. **ヘッダー**（高さ230px）：members 写真をランダム表示（フェーズ3。それまでは photo 色の下地）、上にオーバーレイ。左下に英字キャッチ（11px）とイベント名（font-hand 30px）を paper 色で。
2. 説明文（14px、行間1.8）
3. **確定カード**（フェーズ2・確定時のみ）：背景 navy、角丸14px、余白18px。左に「決定しました」（11px sand）と日時（18px 700）、右に「開催まであと」と日数（font-hand 40px＋「日」16px）。
4. **いい感じの日**（フェーズ2）：上位3件のカード。1位は枠1.5px navy・番号丸が塗り、2・3位は枠1px line・番号丸が線のみ。右に `◯18 △4 ✕2`。
5. **みんなの回答**：見出し右に「24人が回答」。マトリクス表は **行＝候補日、列＝回答者の名前**。日程の列（左端）を `position: sticky` で固定し、名前の列は横スクロール。行の高さ40px、罫線 line。ベスト1位の行は背景 highlight・日付を700に。名前の見出しは11px muted。
6. **ひとこと**：コメントがある人だけ StickyNote で並べる（新しい順）。
7. **写真へのリンク**（フェーズ3）：点線枠（sepia）のカード「あの頃の写真を見る ＞」。
8. **BottomBar**：「回答する」。回答済みの端末では「回答を直す」に変える。

回答0件のときは表の代わりに「まだ誰も回答していません。一番乗りしよう」を出す。

### 3.3 回答フォーム `/e/:slug/answer`（Answer）
1. TopBar（戻る＋イベント名）
2. h1「出欠を書く」
3. Notice（前回の回答を復元したときだけ）「前回の回答を読み込みました。直して保存できます」
4. 「なまえ（みんなに見えます）」TextInput
5. 「都合のいい日」：Card の中に候補日を1行ずつ。左に日時（14px 500）、右に ChoiceButtons。行の区切りは line-soft。
6. 追加アンケート（フェーズ2）：設問ごとにラベル＋Pill 群。設問はイベント設定から動的に出す（例「予算はどれくらい？」「二次会は？」）。
7. 「ひとこと（任意）」テキストエリア（3行、font-hand 16px）
8. 「4桁のPIN」PinInput（フェーズ2）＋補足「別のスマホから直すときに使います」
9. 主ボタン「この内容で保存」

- 全候補日に ◯△✕ のどれかが入るまで保存ボタンは押せるが、押すと未入力の行を maybe 色の枠で示し、最初の未入力行へスクロールする。
- 名前の重複エラーは名前欄の下に表示し、フェーズ2以降は「別のスマホで回答した場合はこちら」として `/edit` へのリンクを添える。

### 3.4 回答完了 `/e/:slug/answer/done`（Done）
上余白96px、中央寄せ。
1. 紙吹雪（フェーズ3は `canvas-confetti`、色は yes・kraft・maybe・navy のみ。reduced-motion なら出さない）
2. h1「ありがとう！」（font-hand 40px）
3. 「{名前}さんの回答を保存しました。この端末なら、いつでも直せます。」
4. 思い出ミニギャラリー（フェーズ3）：ポラロイド3枚を重ねて配置（各120〜140px、`rotate(-7deg)` `rotate(4deg)` `rotate(8deg)`、中央の1枚にテープ）。members 写真からランダム。フェーズ1・2では写真の代わりに photo 色の下地＋キャプション無しで出すか、セクションごと省略する。
5. 下寄せのボタン2つ：副「写真をもっと見る」（フェーズ3のみ）、主「みんなの回答を見る」

### 3.5 写真ギャラリー `/e/:slug/gallery`（Gallery・フェーズ3）
1. TopBar
2. h1「あの頃のアルバム」＋右に枚数（12px muted）
3. FilterChip：「すべて」「新しい順」「自分の投稿」
4. 2列グリッド（列間16px、行間20px）のポラロイド。傾きは -2／1.5／1／-1.5／-1／2deg を順番に。写真は正方形、キャプション14px。
5. 自分の処理中の投稿は、下地 line＋くるくるアイコン＋「処理中…」、キャプション「あなたの投稿」。
6. 補足「写真をタップで拡大。写っていて困る写真は拡大画面の『非表示にしてほしい』から伝えられます」
7. BottomBar：アップロードアイコン＋「写真を投稿する（あと17枚）」。未回答なら「回答すると写真を投稿できます」として回答フォームへ誘導。

拡大表示はページ全体を覆うモーダル（背景は ink の90%）。写真を中央に、下にキャプション・投稿者名・「非表示にしてほしい」（文字ボタン、muted）。自分の投稿なら「削除」も出す。左右スワイプで前後の写真へ。

### 3.6 幹事ログイン `/login`（Login）
上余白120px、左寄せ。
1. Tag（枠線 sepia）「幹事専用」
2. ロゴ「出欠帳」（font-hand 34px navy）
3. 補足「イベントの作成と管理はログインしてから」
4. 「ID」「パスワード」の TextInput（`autocomplete="username"` / `"current-password"`）、主ボタン「ログイン」
5. 下寄せの補足「共同幹事の方は、受け取った管理用URLからそのまま入れます」

失敗時はフォームの上に「IDかパスワードがちがいます」（どちらが違うかは言わない）。

### 3.7 ダッシュボード `/dashboard`（Dashboard）
1. 上部：左にロゴ「出欠帳」（font-hand 22px）、右に人型アイコン（`/settings` へ）
2. 前回のログイン帯：上下を点線（dash）で挟む。時計アイコン＋「前回のログイン：10/26 22:14 ・ パスワード ・ iPhone Safari」
3. h1「わたしのイベント」＋件数
4. イベントカード（Card、間隔12px）：
   - 回答受付中：Tag（塗り navy）、枠1.5px navy、イベント名17px 700、「回答 24 / 38人 ・ 候補 4日 ・ 承認待ち写真 3」、回答率の細いバー（高さ6px、地 highlight、中身 yes）。※「38人」はイベント設定の「クラスの人数（任意）」。未設定ならバーは出さず「回答 24人」とする。
   - 日程確定：Tag（枠 sepia）、「1/3（日）18:00〜 ・ あと67日」
   - 終了：Tag（枠 off）、カード全体を opacity .75、「写真 142枚 ・ 終了から9か月」
5. 点線ボタン「＋ 新しいイベントをつくる」

### 3.8 イベント管理 `/e/:slug/admin`（Admin）
1. TopBar（戻る→ダッシュボード。共同幹事は戻るボタンを出さない）＋Tag「幹事モード」
2. h1 イベント名
3. Tabs：「設定」「アンケート」（フェーズ2）「写真＋承認待ち件数」（フェーズ3）。フェーズ1では「設定」だけでよい。
4. **設定タブ**（Card を縦に並べる）
   - 「みんなに知らせる」（強調枠）：共有URLを paper 地の枠に表示、主色の SmallButton「LINE用の文をコピー」（フェーズ1は「URLをコピー」）、補足「集計の途中経過とURLがまとめてコピーされます」。コピー後はボタン文言を2秒間「コピーしました」に。
   - 「日程を決める」（フェーズ2）：上位3件をラジオで選択、1位の行は highlight。右に `◯18 △4`。主ボタン「この日に決定する」。確定済みなら「決定を取り消す」の副ボタンに。
   - 「候補日」：行ごとにドラッグハンドル（6つの点）、日時、削除（✕アイコン、44×44px）。並べ替えはドラッグ（スマホは長押し）。下に点線 SmallButton「＋ 候補日を追加」→ 日付と時刻の入力が行内に開く。
   - 「合言葉と管理URL」：合言葉の「変更」、共同幹事用URLの「再発行」（注意色。オーナーのみ）。どちらも確認ダイアログを出す。
   - 共同幹事用URLの「コピー」もここに置く。

## 4. 画面デザインがない画面の作り方

既存の部品だけで、上の画面と同じ構成ルール（TopBar → h1 → Card の縦並び → 主ボタン）で作る。

| 画面 | 内容 |
| --- | --- |
| `/events/new` イベント作成 | h1「イベントをつくる」。Card「基本」：イベント名、説明文（テキストエリア）、ゲート写真のキャプション、クラスの人数（任意）。Card「候補日」：日付＋時刻の行を追加・削除。Card「合言葉」：合言葉、終了日。主ボタン「つくる」→ 作成後は共有URLと共同幹事用URLを並べた完了画面（各「コピー」ボタン付き、「管理URLは今しか表示されません」と Notice で注意）。 |
| `/settings` アカウント設定 | h1「アカウント」。Card「パスワード変更」（現在・新しい・確認）。Card「ログイン履歴」（直近20件、日時／方式／端末／成否。失敗は maybe-ink）。Card「他の全端末からログアウト」（注意色 SmallButton）。最下部に文字ボタン「ログアウト」。 |
| `/e/:slug/edit` 別端末から編集 | h1「回答を直す」。名前を選ぶ（回答者の名前をセレクトで）→ PinInput → 主ボタン「ひらく」。5回失敗時「15分ほどおいてからもう一度試してください」。 |
| `/e/:slug/gallery/upload` 写真投稿 | h1「写真を投稿」。大きな点線エリア「写真をえらぶ」（複数選択可、`accept="image/*"`）。選んだ写真をポラロイドの小サムネイルで並べ、各下にキャプション入力。補足「位置情報は自動で消えます」。主ボタン「投稿する」。送信中は各サムネイルに進捗を出す。 |
| 写真管理（Admin「写真」タブ） | フィルタ「承認待ち／公開中／非表示依頼／下書き」。2列のポラロイドに、承認・却下・公開範囲（public／members／draft のセグメント）を付ける。非表示依頼は理由を表示して「非表示のままにする／元に戻す」。 |

## 5. 状態の見せ方

- **読み込み中**：スピナーは使わない。カードの形をした highlight 色のプレースホルダーを出す（ふわっと明滅、reduced-motion なら静止）。
- **エラー**：画面上部に Notice を maybe-ink の文字で。「通信できませんでした。もう一度試してください」＋「再読み込み」文字ボタン。
- **空の状態**：font-hand 18px の一言＋補足（例「まだ写真がありません」）。イラストは入れない。
- **成功**：画面遷移かボタン文言の変化で伝える。トースト通知は使わない。
- **トースト（例外。修正03・04）**：トーストは原則使わないが、次の2つだけ使ってよい。
  - シートやダイアログを開いているときの通信エラー（その場に Notice を出すと、シートの中で見えない位置に出ることがあるため）
  - 管理画面での削除操作の結果（成功・失敗）。例：写真を削除したとき「写真を削除しました」、失敗したときのエラー
  - 参加者向けの画面では、通信エラー以外に使わない。
  - 表示場所：いちばん手前の開いている dialog（シート・確認ダイアログ）の中。なければページ本体。出している dialog が閉じたら、次に手前の dialog かページ本体へ移す。画面の下に1つだけ、6秒で消える。閉じるボタン（44×44px）を付ける。
  - 見た目：Notice と同じ（背景 highlight、角丸10px、12px、左にアイコン16px）に、軽い影 note。色は2種類だけ：エラーは maybe-ink、結果はセピア（sepia-ink）。
  - 動き：fade-in だけ。reduced-motion なら動かさない。
  - 既知の課題：読み上げ用の領域（role="alert"／"status"）を文言と同時に作っているため、読み上げソフトによっては読まれない。

## 6. レスポンシブ

- 基準は幅390px。最小は360pxで崩れないこと。
- 幅640px以上では、コンテンツ幅を最大480pxにして中央寄せ（背景の方眼は全幅）。PCでもスマホと同じ1カラム。
- ヘッダー写真は幅いっぱい、高さは 230px 固定。

## 7. ダークモード（フェーズ3）

`prefers-color-scheme: dark` で**黒板テーマ**に切り替える。背景は深い緑がかった黒（例 `#1F2A26`）に方眼の代わりにチョークのかすれ、文字はチョーク色（`#EDEAE0`）、カードは少し明るい黒板色。ポラロイドの白枠はそのまま白で残す（黒板に貼った写真に見えるように）。色はトークンを差し替えるだけで切り替わるよう、CSS変数でトークンを定義しておく。
