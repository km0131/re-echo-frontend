始める前に：
- `docs/spec-fix01.md` を `docs/spec.md` の末尾に「11. 修正01」として追記しておくこと。

## ステップ FF1-1：合言葉ゲートの日本語対応と質問の表示

```
docs/spec.md 11.1 に沿って、合言葉の入力と設定を直してください。

まず原因の特定：
- 日本語の合言葉が入らない／通らない原因をフロント側で確認し報告する。特に次を見る：
  - 入力欄が type="password" になっていないか（iOS Safari などで日本語入力が使えない）
  - pattern、inputMode="latin"／"url"／"email"、maxLength がバイト前提になっていないか
  - 送信前に英数字以外を削る処理や toLowerCase 以外の変換が入っていないか
  - Enter キーで送信していて、日本語変換の確定（IME の Enter）で誤送信していないか

やること：
1. 合言葉ゲート（/e/:slug 未通過時）
   - 入力欄は type="text"、autoComplete="off"、autoCapitalize="off"、autoCorrect="off"、spellCheck={false}、enterKeyHint="go"
   - IME 変換中（e.nativeEvent.isComposing、または keyCode 229）の Enter では送信しない
   - passphraseQuestion があれば、入力欄の上に質問を表示する
     - 見せ方：黒板に書かれたチョークの問題文のように、手書き風フォント（Zen Kurenaido）で「Q.」を添えて表示
     - 例：「Q. 担任の先生の名前は？」
     - 質問が無いときは従来どおり「合言葉を入れてね」
   - 間違えたとき：「ちがうみたい。ひらがな・カタカナ、全角・半角はどちらでも大丈夫です」と補足を出す
   - 入力値は trim だけして送る（正規化はサーバーでやる）
2. イベント作成（/events/new）と管理画面の設定タブ（/e/:slug/admin）
   - 「合言葉の質問（任意）」入力欄。プレースホルダー：「例）担任の先生の名前は？」
   - 「答え」入力欄を1〜5個。「別の答えを追加」で増やす（例：田中先生／たなかせんせい／田中）
   - 補足文：「ひらがな・カタカナ、全角・半角、スペースの違いは自動で同じとみなします。漢字とかなの違いは別の答えとして足してください」
   - 管理画面では答えそのものは表示できない（サーバーが返さない）。「答え：3つ登録済み」と表示し、「答えを変更」で入力し直す形にする
   - 答えを変更するとき：「変更すると、みんなもう一度合言葉を入れ直すことになります」と確認を出す
   - 質問だけの変更は確認なしで保存してよい
3. 文字数の表示・チェックは [...str].length（コードポイント数）で数える

完了条件：
1. iPhone（Safari）と Android（Chrome）の実機、またはそれぞれのエミュレーションで、
   日本語入力のまま合言葉を入れて通過できる。変換確定の Enter で誤送信しない
2. 質問ありのイベントと、質問なしのイベントでゲートの表示を見せる（スクリーンショット）
3. 答えを3つ登録し、別解でも通過できる
4. npm run build、npm run lint が通る
```

## ステップ FF1-2：写真のタイトル

```
docs/spec.md 11.2 に沿って、写真にタイトルを付けられるようにしてください。

やること：
1. 写真投稿（/e/:slug/gallery/upload）
   - 選んだ写真ごとに、サムネイルの下（ポラロイドの下の余白部分）にタイトル入力欄を置く
     - プレースホルダー：「タイトル（なくてもOK）」
     - 最大40文字。残り10文字を切ったら残り文字数を出す
   - 送信時に multipart の meta に [{ title }] を files と同じ順で入れる
2. ギャラリー（/e/:slug/gallery）
   - ポラロイドの下の白い余白に、タイトルを手書き風フォントで書く（写真の裏にペンで書いたような見え方）
   - タイトルが無い写真は余白のまま（「無題」などと出さない）
   - 1行に収まらなければ省略記号（…）、拡大表示では全文
3. 写真の拡大表示
   - 自分が投稿した写真（編集トークンが一致）なら、タイトルの横に小さな「なおす」ボタン。その場で編集できる
4. 管理画面の写真タブ
   - タイトルの表示と編集

完了条件：
1. 3枚まとめて投稿し、それぞれ別のタイトルが付いて表示される（スクリーンショット）
2. 長いタイトルがカードからはみ出さない（390px 幅で確認）
3. 他人の写真には「なおす」が出ない
```

## ステップ FF1-3：写真のコメント

```
docs/spec.md 11.3 に沿って、写真の拡大表示にコメント欄を付けてください。

デザインの方向：
- コメントは「写真の横に貼られた付箋」。付箋1枚に1コメント。
- 付箋の色は design.md のセピア系の淡い色から2〜3色を、コメントIDから決めて固定（再描画で色が変わらないこと）
- 付箋はわずかに傾ける（±1.5° 程度。prefers-reduced-motion 時も静止した傾きは可）
- 本文は手書き風フォント（ひとことコメントの例外ルールと同じ扱い）、名前と日時は Noto Sans JP で小さく
- 名前が無いコメントは「だれか」と表示
- 新しい付箋が増えるときは、ふわっと貼られるだけ（大げさなアニメーションはしない）

やること：
1. 拡大表示（ライトボックス）
   - スマホ：写真の下にコメント欄。写真を左右にスワイプして移動したら、その写真のコメントに切り替わる
   - PC（幅 768px 以上）：写真の右側にコメント欄
   - 一覧は古い順。件数が多いときは欄の中だけスクロール
2. 投稿フォーム（コメント欄のいちばん下）
   - 名前（任意）：プレースホルダー「名前（なくてもOK）」。回答済みの端末なら自分の回答名を初期値に入れる。消して空にもできる
   - 本文：textarea、プレースホルダー「この写真のこと、ひとこと」。最大200文字、残り20文字を切ったら残り文字数
   - 送信ボタン「貼る」
   - IME 変換中の Enter で送信しない。送信は「貼る」ボタンか Ctrl/⌘+Enter
   - 送信中はボタンを無効化して二重投稿を防ぐ
   - 投稿後は本文だけ空にする（名前は残す）
3. 自分のコメント
   - deleteToken を LocalStorage の chosei:comments:{slug} に保存（{ [commentId]: token }）
   - 一覧取得時に X-Comment-Tokens でトークンを送り、mine: true のものに小さな「はがす」ボタン
   - 「はがす」は確認を1回出してから削除
4. ギャラリーのサムネイル
   - commentCount が1以上なら、ポラロイドの右下に小さな付箋マーク＋件数（例：付箋の形の中に「3」）
5. 管理画面の写真タブ
   - 写真ごとにコメント一覧（hidden も含む）。各コメントに「非表示にする／戻す」「削除」
6. エラー表示
   - 429：「少し時間をおいてから書きこんでください」
   - それ以外は spec.md のエラーメッセージをそのまま出す
7. TanStack Query：コメント一覧は ['photo-comments', slug, photoId]。投稿・削除後に一覧と写真一覧（commentCount）を invalidate。
   SSE の photo_comment イベントが来たら同じく invalidate

注意：
- 本文は必ず React のテキストとして描画する（dangerouslySetInnerHTML を使わない）
- 改行は white-space: pre-wrap で表示

完了条件：
1. 名前あり・名前なしでコメントでき、名前なしは「だれか」と出る
2. 自分のコメントだけに「はがす」が出て、消せる。別のブラウザ（別端末扱い）では出ない
3. 回答済みの端末では名前欄に回答名が入っている
4. 390px 幅と 1280px 幅の拡大表示のスクリーンショット
5. 日本語入力の変換確定 Enter で誤送信しない
6. npm run build、npm run lint が通る
```
